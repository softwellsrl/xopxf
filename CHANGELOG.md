# Changelog

All notable changes to the XOPXF format are documented here. The format follows
semantic versioning; backward compatibility is intended within a major version.

## [0.1.0] — alpha draft

First public draft of the format. The standard version is `0.1.0` (alpha): the
three schemas are complete and validated, but the shape may still change within
the `0.x` series. XML namespaces carry the major version
(`urn:xopxf:budget:1.0`, `urn:xopxf:costreport:1.0`, `urn:xopxf:details:1.0`).

### Added

- **Budget** document:
  - XML Schema `schema/budget/budget.xsd` with self-contained `<Header>`
    (vocabularies) and `<Header>`/`<Body>` separation.
  - Synthetic and analytic profiles (the analytic profile adds the optional
    `<Item>` level between `<Account>` and `<Detail>`).
  - Multi-axis chapter grouping via `<GroupRef>` referencing `<Group>` entries
    that carry a `scheme`.
  - XSLT views (budget body and header / data dictionary) and worked analytic +
    synthetic examples (same total).
  - Namespace: `urn:xopxf:budget:1.0`.
- **Cost Report** document:
  - XML Schema `schema/cost-report/cost-report.xsd`, same Header/Body design and
    synthetic/analytic profiles as Budget.
  - `<BudgetReference>` linking the report to a specific confirmed budget
    revision (production code + revision number).
  - Per-line metrics (budget, spentToDate, committed, costToDate, reserve, efc,
    variance, estToComplete) and an optional `<Benchmark>` against a previous
    report.
  - XSLT view with overrun highlighting; worked analytic + synthetic examples.
  - Namespace: `urn:xopxf:costreport:1.0`.
- **Details** document:
  - XML Schema `schema/details/details.xsd` — analytic movements (invoices,
    purchase orders, payroll, variations) that justify a cost report. Same
    Header/Body design; analytic only (no synthetic profile).
  - `<BudgetReference>` and `<CostReportReference>` linking the movements to the
    cost report and budget revision they explain.
  - **Personal-data minimisation by design**: counterparties live in an optional
    `<Parties>` registry keyed by code; movements reference a payee by code only
    (`payeeRef`). Transmitting the registry resolves codes to names; omitting it
    keeps personal data with the issuer. `payeeRef` is a soft reference so the
    minimised form stays valid.
  - Optional per-movement `<Document url="…">` link to the source PDF.
  - XSLT view resolving codes to names when the registry is present; worked
    `full` and `minimized` examples (identical bodies).
  - Namespace: `urn:xopxf:details:1.0`.
- **Localization**: HTML views in six languages (en, it, fr, de, zh, ko) from
  neutral templates + per-language dictionaries, generated by `regen.py`.
  Number formatting (decimal/grouping separators and pattern) is per-language.
- **Tooling**: `regen.py` (templates + dictionaries → localized XSLT) and
  `render_examples.py` (examples + XSLT → localized HTML + per-folder indexes).
- **Documentation** under `docs/` (MkDocs site): specification, a page per
  document, localization, validating & rendering, and an FAQ.

### Fixed

- **Referential integrity now enforced.** The `key`/`keyref` identity
  constraints in all three schemas were inert because their `xs:selector` /
  `xs:field` XPaths used unprefixed element names, which do not match elements in
  the target namespace. The selectors now use an explicit namespace prefix, so a
  dangling reference (an undeclared group, role, department, type…) correctly
  fails validation.
- **Localized labels in the budget HTML view.** The budget body template carried
  several header labels hard-coded in Italian, so they appeared untranslated in
  every language; they now use the dictionary placeholders.
- **Per-language number formatting.** Number separators were hard-wired to the
  Italian convention in all languages; they are now driven by the per-language
  dictionary (`num_decimal`, `num_grouping`, `num_pattern`).
